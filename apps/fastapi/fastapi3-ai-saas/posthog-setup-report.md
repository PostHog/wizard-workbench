# PostHog post-wizard report

The wizard has completed a deep integration of PostHog analytics into this FastAPI SaaS application. The following changes were made:

- **`requirements.txt`** — Added `posthog>=6.0.0` dependency.
- **`.env`** — Added `POSTHOG_API_KEY` and `POSTHOG_HOST` environment variables (never committed to source control).
- **`app/config.py`** — Added `posthog_api_key` and `posthog_host` fields to the Pydantic `Settings` class.
- **`app/posthog_client.py`** _(new)_ — Creates a `Posthog` instance using env-based settings, with `enable_exception_autocapture=True` and `atexit` shutdown registration.
- **`app/main.py`** — Imports the PostHog client and calls `posthog_client.flush()` on application shutdown via the lifespan context manager.
- **`app/routers/auth.py`** — Captures `user signed up`, `user logged in`, and `login failed` events; users are identified via `identify_context` on signup and login.
- **`app/routers/generate.py`** — Captures `content generated` (with generation type, credits used/remaining, and prompt length) and `content generation failed` (with reason and credit details).
- **`app/routers/api_keys.py`** — Captures `api key created` and `api key revoked` events.
- **`app/routers/settings.py`** — Captures `settings updated` (email change) and `password changed` events.

All events use the `new_context()` + `identify_context(str(user.id))` pattern to associate events with the correct user. No PII is sent in event properties.

## Events

| Event | Description | File |
|---|---|---|
| `user signed up` | Fired when a new user successfully creates an account via the signup form. | `app/routers/auth.py` |

| `login failed` | Fired when a login attempt fails due to invalid credentials. | `app/routers/auth.py` |

Recommended insights for the dashboard:

2. **Daily Signups & Logins** — Trend chart of `user signed up` and `user logged in` by day to track user acquisition and retention.

4. **Credit Exhaustion (Churn Signal)** — Trend of `content generation failed` events — users hitting credit limits represent churn risk.
5. **API Adoption** — Weekly trend of `api key created` vs `api key revoked` to track developer engagement and API key churn.
