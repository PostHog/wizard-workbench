# PostHog MCP Analytics — Instrumentation Report

## Summary

The MCP server (`workbench-stdio-server`) has been instrumented with PostHog MCP analytics using **Path A** — the official `@modelcontextprotocol/sdk` `McpServer` wrapper pattern.

## What changed

### Instrumentation path

- **Language:** TypeScript
- **Server style:** `McpServer` (high-level, `@modelcontextprotocol/sdk/server/mcp.js`)
- **Transport:** STDIO (long-running process)
- **Instrumentation path:** Path A — `instrument(server, posthog)` called immediately after `McpServer` construction

Every tool call (`echo`, `add`), tools-list request, and client handshake will now emit `$mcp_*` events to PostHog.

## Manual steps

1. **Load `.env` at runtime.** The server reads `POSTHOG_PROJECT_TOKEN` and `POSTHOG_HOST` from environment variables. If you run it directly with `npm start`, load the file first (e.g. `dotenv -e .env -- npm start`, or use a dotenv loader in your dev setup). In production, inject the vars via your deployment platform's secrets manager.

2. **Do not commit `.env`.** The file was added to `.gitignore` automatically, but double-check before pushing.

3. **Upgrade `@posthog/mcp` carefully.** The SDK is pre-1.0 — minor releases may have breaking changes. Check the [changelog](https://github.com/PostHog/posthog-js/releases) before upgrading.

## Events you'll see in PostHog

Once the server handles its next request, you'll see these events in the [MCP Analytics dashboard](https://posthog.com/docs/mcp-analytics):

- `$mcp_initialize` — per client connection
- `$mcp_tools_list` — per `tools/list` request
- `$mcp_tool_call` — per `echo` or `add` call (includes tool name, parameters, duration, and success/error)
- `$exception` — if a tool throws or returns `isError: true`

See the full event reference at https://posthog.com/docs/mcp-analytics.
