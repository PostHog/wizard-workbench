# PostHog MCP Analytics — Setup Report

## What was done

This MCP server (`workbench-stdio-server`) was instrumented with PostHog MCP analytics using **Path A** — the official `@modelcontextprotocol/sdk` v1 `McpServer` wrapper via `instrument(server, posthog)`.

Once the server handles its next request, `$mcp_*` events will appear in PostHog. See the [event and dashboard reference](https://posthog.com/docs/mcp-analytics) for details.

## Files modified or created

| File | Change |
|------|--------|
| `src/index.ts` | Added `posthog-node` client, `instrument()` call with `captureModel: true`, env-var guards, and a `SIGTERM` shutdown handler |
| `package.json` | Added `@posthog/mcp@^0.13.0` and `posthog-node@^5.51.6` as dependencies |
| `package-lock.json` | Generated by `npm install` |
| `.env` | Created with `POSTHOG_PROJECT_TOKEN` and `POSTHOG_HOST` |

## Events captured

| Event | When |
|-------|------|
| `$mcp_initialize` | On each `2025-11-25` client handshake |
| `$mcp_tools_list` | On each `tools/list` response |
| `$mcp_tool_call` | On each tool invocation (`echo`, `add`) |
| `$exception` | Whenever a tool throws or returns `isError: true` |

With `captureModel: true`, each tool call also records `$mcp_llm_model` (the agent's self-reported model) and `$mcp_llm_model_source = "self_reported"`.

## Manual steps

- **Env vars are already set** in `.env` (token `phx_API_KEY_IS_HARDCODED`, host `https://us.i.posthog.com`). If you deploy to a hosted environment, set `POSTHOG_PROJECT_TOKEN` and `POSTHOG_HOST` in your environment/secrets manager rather than shipping the `.env` file.
- **`@posthog/mcp` is pre-1.0 (beta).** The API may change in minor `0.x` releases. Pin or review before upgrading.
- Start the server with `npm start` (or `tsx src/index.ts`). Events are flushed on `SIGTERM` via `posthog.shutdown()`.
