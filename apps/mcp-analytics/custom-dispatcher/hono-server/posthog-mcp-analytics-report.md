# PostHog MCP Analytics — Instrumentation Report

## What was done

This Hono-based custom MCP dispatcher was instrumented using **Path C** (custom dispatcher) from the `@posthog/mcp` SDK. Because the server speaks the MCP JSON-RPC protocol directly without a `@modelcontextprotocol/sdk` server object, `instrument()` cannot be used. Instead, `PostHogMCP` is used as a drop-in replacement for the PostHog client, with explicit `captureToolCall` and `captureInitialize` calls at each dispatch point.

## What gets captured

Once the server handles requests, you will see the following `$mcp_*` events in PostHog:

- **`$mcp_initialize`** — fired on every MCP handshake, with client name/version and session ID
- **`$mcp_tool_called`** — fired after every `tools/call`, including tool name, parameters, response, duration, and error flag
- **`$exception`** — automatically emitted alongside any failed tool call (when `isError: true`)

## Manual steps

1. **Load `.env` at startup.** The server reads `POSTHOG_PROJECT_API_KEY` and `POSTHOG_HOST` from `process.env`. Load the `.env` file before starting — for example with `dotenv` in development, or by injecting the variables in your deployment environment.

2. **Deploy / restart the server.** Once running, the next MCP request will produce events visible in PostHog.

3. **View events.** Visit your PostHog project and filter for `$mcp_*` events. See the full dashboard and event reference at https://posthog.com/docs/mcp-analytics.

> **Note:** `@posthog/mcp` is pre-1.0. Pin the version and check the changelog before upgrading.
