# PostHog MCP Analytics — Instrumentation Report

## Instrumentation path

**Path C — Custom HTTP dispatcher (Hono)**. This server speaks the MCP JSON-RPC protocol directly over HTTP with no `@modelcontextprotocol/sdk` server object to wrap, so `PostHogMCP` is used instead of `instrument()`.

## Changes made

### `src/index.ts`
- Imported `PostHogMCP` from `@posthog/mcp` at the top.
- Constructed a single module-scope `PostHogMCP` client reading credentials from `process.env.POSTHOG_PROJECT_API_KEY` and `process.env.POSTHOG_HOST`.
- Added `posthog.captureInitialize(...)` inside the `initialize` handler, forwarding the MCP client name and version from the request's `clientInfo`.
- Added `posthog.captureToolCall(...)` in both the success and error branches of the `tools/call` handler, recording tool name, parameters, response, duration, and error flag.
- Added a `SIGTERM` handler that calls `await posthog.shutdown()` before exiting to drain any queued events.

### `package.json`
- Added `@posthog/mcp` pinned to `0.7.0` (exact, not `^`, because the SDK is pre-1.0).
- Added `posthog-node` at `^5.39.2`.

### `.env` *(created)*
- `POSTHOG_PROJECT_API_KEY` — your PostHog project API key.
- `POSTHOG_HOST` — `https://us.i.posthog.com`.

## Next steps

1. **Verify the `.env` values** — the file was written with the PostHog project token from your session context. Confirm they match your intended project.
2. **Start the server** — `npm start` (or `tsx src/index.ts`). After the first `initialize` or `tools/call` request arrives, you will see `$mcp_initialize` and `$mcp_tool_called` events in PostHog.
3. **Note: `@posthog/mcp` is pre-1.0** — it is pinned at `0.7.0` exactly. Check the [changelog](https://github.com/PostHog/posthog-js/releases) before upgrading.
4. **Dashboard and event reference** — see [https://posthog.com/docs/mcp-analytics](https://posthog.com/docs/mcp-analytics) for the built-in MCP analytics dashboard and the full `$mcp_*` event/property reference.
